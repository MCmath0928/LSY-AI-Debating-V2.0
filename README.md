# ⚔️ AI 辩论（人机对辩）

一个托管在 GitHub Pages 的**纯静态网页**：你选择辩题与持方，与 **DeepSeek** 进行一场完整赛制的中文辩论对抗，最后由独立的 AI 评委裁决胜负。

> 创作者：Fzyz LSY

## 功能

- **完整辩论流程**（14 个环节，顺序固定）：
  正方一辩立论 → 反方四辩质询正方一辩 → 反方一辩立论 → 正方四辩质询反方一辩 → 正方二辩申论 → 反方三辩质询正方二辩 → 反方二辩申论 → 正方三辩质询反方二辩 → 评委提问 → 反方三辩小结 → 正方三辩小结 → 自由辩论 → 反方四辩结辩 → 正方四辩结辩
- **时间 → 字数**：按中文辩论语速约 250 字/分钟换算（3 分钟 ≈ 750 字，2 分钟 ≈ 500 字），通过限制输入/输出字数实现时间限制。
- **质询打断逻辑**：质询环节每次提问/回答 **≤ 150 字**，模拟快速打断。
- **自选辩题、自选持方**：AI 自动持相反持方。
- **宏观战略**：开场前 AI 用最深思考（`reasoning_effort=max`）生成整场战略，并保存；每个环节加载该战略 + 辩论正文（**不含思考过程**）进行多轮思考后输出正文。
- **AI 评委**：赛后拉取新对话，输入辩题与辩论正文，输出完整裁决（复盘 / 逐环节点评 / 胜负判定 / 七维评分表 / 建议）。
- **自定义 API Key**：支持在页面配置自己的 DeepSeek API Key（保存在浏览器 localStorage）。
- **导出记录**：一键导出辩论实录（Markdown）。
- **思考进度与调试**：AI 思考时实时显示"已思考 N 字 · X 秒"进度；辩论页可勾选「显示 AI 思考（调试）」、战略/裁决页可展开「💭 思考过程」，流式查看思维链，确认 AI 确实在思考。
- **流程总览**：点击辩论页顶部的「流程 x/14」可展开查看完整环节与进度（✓ 已完成 / ▶ 当前 / ○ 未开始）。
- **高级设置 / 自定义赛制**：开始前点击「高级设置」，可自定义赛制（增删/排序环节，修改类型、持方、辩位、时长与每环节最大字数）、质询问答回合数、自由辩论每方字数预算与总回合上限，保存后立即生效并持久化到浏览器。

## 快速开始

1. 复制或克隆本目录。
2. 用浏览器打开 `index.html`（直接双击即可；若需要完整功能与跨域，建议通过 GitHub Pages 或本地静态服务器访问）。
3. 填入你的 [DeepSeek API Key](https://platform.deepseek.com/)、辩题、持方，点击「开始」。
4. 等待 AI 生成宏观战略 → 「进入辩论」→ 按环节发言或观战。

> 说明：密钥只存在你本机浏览器，仅发往 `https://api.deepseek.com`。本项目为私人小众用途，未做密钥保护（这是有意的取舍）。

## 部署到 GitHub Pages

1. 新建仓库，把本目录所有文件推送到仓库根目录。
2. 仓库 **Settings → Pages**，Source 选 `main` 分支、根目录 `/ (root)`，保存。
3. 稍等片刻，访问 `https://<你的用户名>.github.io/<仓库名>/`。

纯静态、无构建步骤，推上去即可用。

## 技术要点

- **分角色模型**：宏观大纲用 `deepseek-v4-pro`，辩论过程（14 个环节 + 评委提问）用 `deepseek-flash`，评委裁决用 `deepseek-v4-pro`（在 `config.js` 的 `MODELS` 中配置）。接口为 OpenAI 兼容的 `https://api.deepseek.com/chat/completions`。
- **思考模式（多轮思考）**：V4 Pro 原生支持 `{"thinking":{"type":"enabled"}}` + `reasoning_effort: low/high/max`。模型先在思维链（`reasoning_content`）中深度思考，最终只输出 `content`。
- **只保留正文**：代码在流式解析时把 `reasoning_content`（思维链）**仅用于进度显示与调试**，不写入辩论实录；DeepSeek 在无 `tools` 的多轮对话中也不会把思维链拼回上下文 —— 与「保存正文、不含思考过程」的需求完全一致。
- **输出 token 上限**：思考模式下 `reasoning_content` 与 `content` 共享 `max_tokens` 预算，故各环节 `max_tokens` 都设得足够大（见 `config.js` 的 `MAX_TOKENS`），避免思维链耗尽预算导致正文被截断或为空；代码还会检测空回复并给出重试。
- **每个环节 = 一次全新请求**：system（辩手人设 + 本环节职责）+ user（辩题 + 持方 + 宏观战略 + 辩论实录 + 任务），避免对话漂移、保证上下文完整。

## 提示词工程：如何解决 AI 辩论六大缺陷

所有提示词集中在 `prompts.js`。设计思路：

| 缺陷 | 对策 |
| --- | --- |
| ① 缺乏战略规划与宏观架构 | 开场「策略家」阶段输出完整宏观战略（辩题解析/核心立场/论点架构/对方预判/攻防布局/环节分工/事实风险清单），每个环节都重新加载该战略 |
| ② 战术僵化与缺乏临场博弈 | 「辩手铁律」第 2 条：逐字研读实录、针对对手实际措辞拆解、优先攻击最新漏洞、禁用脱节套话 |
| ③ 易受逻辑谬误与说服影响 | 「铁律」第 3、4 条 + 「思考步骤」的逻辑自检：拆解前提—推理—结论、规避谬误、只回应逻辑内核 |
| ④ 同质化与多样性不足 | 「铁律」第 7 条 + 每个辩位独立的职责与语体（立论/申论/小结/结辩/质询/自由辩论各不相同） |
| ⑤ 事实性错误与幻觉 | 「铁律」第 5 条 + 事实自检：禁编造数字/人名/研究/引文，不确定用谨慎措辞；战略阶段输出「事实风险清单」 |
| ⑥ 说服力与理解深度错位 | 「铁律」第 6 条：先清晰后深刻、理性（逻辑）与感性（价值）并重 |

此外，模型通过统一的**「思考步骤」模板**（局面盘点 → 对方破绽 → 本方目标 → 逻辑自检 → 事实自检 → 表达设计）在思维链中完成多轮思考，最终只输出正文。

## 注意事项

- 思考模式下 `temperature` 等参数不生效（V4 Pro 特性），以 `reasoning_effort` 控制思考深度。
- 若浏览器直开 `index.html` 时 API 请求被跨域拦截，请改用 GitHub Pages 或 `python -m http.server` 等本地服务器访问（DeepSeek API 本身允许浏览器跨域调用）。
- 字数限制为「约等于」：模型偶有超限，代码会在输入侧严格校验，输出侧由提示词约束。
